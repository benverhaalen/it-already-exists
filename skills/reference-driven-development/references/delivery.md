# Build, verify, and improve the method

Before substantial implementation, establish a representative complete journey from normal entry/default state to useful outcome. Use an early complete slice to test the approach while preserving the full requested ambition. Specifications and research are intermediate deliverables when the user authorized implementation.

Pass transfer contracts into actual implementation assignments and checks. Give workers the objective, permitted evidence, constraints, dependencies, uncertainty, and one coherent deliverable. Keep work together when splitting would increase handoff and repair costs. When independent judgment matters, collect it before revealing favored conclusions.

For important properties, trace:
1. What the reference actually supports.
2. Why it fits the target audience and situation.
3. Which operation/file/artifact implements the property.
4. Which check discriminates success from plausible failure.
5. What happens across the complete journey.

Verify the actual deliverable with domain-appropriate tools: rendered visuals and interactions, API behavior, persistence/restart, signal measurements, document renders, or observed physical use. Unit tests and schemas support the judgment; they cannot alone establish taste, factual truth, faithful behavior, or user value. Preserve actual failed results, not just intended checks. Exercise consequential offered choices through their effects: a prompt displaying both “keep” and “discard” is not complete recovery if one choice is a no-op. Use counterexamples and realistic branching journeys, not only the path the implementation already handles.

For a material failure or consequential reliability work, apply [failure-family review](failure-families.md): bind the counterexample to the actual run, inspect sibling contracts, and verify completion and durable results. The agent manages this investigation and records its limits; the user need not enumerate the checks.

When observed use contradicts passing checks, reconsider the objective, framing, evidence, and evaluator before repeatedly patching the same output. Compare challengers or ablate a consequential mechanism when causality matters. Treat agreement between agents as agreement, not proof.

Track whole-investigation costs: discovery, source reading, acquisition readiness, model/tool usage, coordination, retries, integration, and repair. Compare on equivalent tasks and budgets. Record unknown costs honestly. Cache reuse needs runtime evidence and validity conditions; a routing recommendation is not an applied cache-preserving mechanism.

Fast/System One models may help with candidate ranking, scoped extraction, triage, or uncertainty escalation. Test them against representative cases and a simple baseline, inspect difficult errors, and account for downstream repair. Do not use confidence alone as permission to discard ideas or certify equivalence. Escalate consequential ambiguity to richer evidence or stronger evaluation.

Store lessons with scope, evidence, causal hypothesis, and revisit trigger. Change the operation that failed and its dependent decisions. Compare improvements on fresh held-out cases before generalizing; preserve version and rollback. Project-local feedback does not automatically become a global prohibition.

When transferring an expert method or creating reusable guidance, use the [expert-process checks](expert-processes.md#test-the-contribution-and-its-carrier). Distinguish changed judgment from the benefit of its packaging; inspect actual outputs, exception handling, activation/retrieval, runtime capability, and whole-cycle cost.

For later evaluation of this skill, use independent realistic forward tests with raw fixtures and no intended answer. During the currently authorized early implementation, the user reserves actual reconstruction scenarios for his own testing; use focused synthetic mechanical checks and source-informed critical review instead. Inspect actual artifacts and failed cases. Evaluate across domains and compared budgets over time; do not claim broad effectiveness from one synthetic scenario or structural validation.

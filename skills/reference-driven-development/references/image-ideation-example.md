# Use images to discover product direction

Use with [UI continuity](ui-continuity.md). Image generation can explore product
jobs and interaction arrangements before the chat model fixes a layout. A
selected image can later become a precise implementation reference.

Start with the unresolved decision, actual reference pixels, audience and a
representative journey moment. Preserve explicit constraints. Let the image
model propose composition, hierarchy and visual relationships. An identical
brief can expose variation; a changed journey moment can expose a different
product interpretation. Do not impose a fixed number of generations.

Compare the action each candidate helps the user take, its information hierarchy,
and its contribution to the intended outcome. Preserve small useful differences.
Do not combine every proposed feature into one screen. Generated content and
capabilities are hypotheses, not evidence that they exist or should be built.

If an attractive output does not help the intended decision, sharpen the user
situation rather than prescribing the entire screen. Give each reference its
specific job. A component study can establish utility geometry without supplying
the composition; an atmospheric image can establish character without supplying
interaction behavior. Keep exact font identity and density anchored in actual
assets and rendered controls.

For consequential direction choices, obtain fresh-context critique of the actual
reference and candidate images. Withhold the favored answer. Ask for localized
observations, proposed repairs and unresolved alternatives. Reconcile findings
against the pixels and intended journey; agreement alone is not approval.

Retain discoveries in contribution and decision records. A generated invention
remains a candidate until selected. Once direction is settled, give the builder
the chosen image, usable font/icon assets, behavior and deliberate adaptations.
Compare the coded result to the image and test the complete journey separately.
Private source images, prompts, reviews and project names do not belong in the
portable process. Keep their general mechanisms and qualification limits here.

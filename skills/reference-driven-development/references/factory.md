# Installed factory execution

Use for substantial creation, improvement or reconstruction. This is the execution
profile of RDD, not a second agent scheduler or a new conversation. Keep native
dialogue, current model, permissions, history and resume. Use existing project
controls, evidence stores and host delegation where qualified. Simple tasks stay
direct. Never equate installation with successful use or universal capability.

## Bind the complete task

Recover the original outcome, audience, complete scope, constraints, relevant
references, prior decisions and corrections. Establish the normal entry, default
state, complete journey, durable outcome and reset. Preserve actual text and
attachments; an image path in a prompt does not prove pixels reached a model.
Keep missing native identities explicit. Do not replace the user's full objective
with the first local slice or a collection of independently accepted subtasks.

Use one private task-owned RDD journal, preferably the project's existing store.
The deterministic runtime is `scripts/factory.py`; its `--help` and JSON request
validation describe the installed interfaces. Its events use the existing RDD
journal. Do not create a parallel central task tracker or copy full transcripts.
Save current task input, requirements, selected source identity and relevant
original evidence before compaction or handoff. Keep private evidence outside
public commits. Every action needs only the requirements and source dependency
closure that can affect it, including short corrections and unresolved effects.

At substantial task admission, create the request yourself from the native
conversation; the user never fills out factory forms. Run these commands using
the actual installed skill directory and the existing private journal:

```sh
python3 scripts/factory.py --store /private/task/records.jsonl bind --request /private/task/intake.json
python3 scripts/factory.py --store /private/task/records.jsonl --root task-id compile
python3 scripts/factory.py --store /private/task/records.jsonl --root task-id status
python3 scripts/factory_procedures.py select feature
```

The intake has `root_task_id`, actual `native_identity` (`host`, `session`,
`turn`; unknown identities stay explicitly unknown), exact `full_text`, the
existing workflow `task` shape, complete `requirements` (`id`, `property`,
`description`), `authorization_scope`, actual `attachments` (`path`, `required`,
`role`) and root `resource_limits` (at least `operations` and `episodes`).
The task includes scope, goal, audience, surface, operation, access, complete
entry/default/action/outcome/reset journey, and explicit competence/character
criteria. Use `references/workflow.md` for its existing schema and selection.
Record an empty selection's reason while investigating; bind the adopted
contributions and transfers before claiming reference application.

Read the compiled packet and ordered selected source bytes before the actual
producing operation. Preserve the selected source closure and effective
adaptations in that operation's input. Native tools can consume the packet
directly; their actions remain outside helper interception. For an owned
subprocess, reserve its root allowance, then use `factory.py ... prepare --request`
to bind the exact current context capsule. Its output is the request for
`factory.py ... run --request`, with the exact command array, current revision,
source closure, target manifest, write set and transfer associations. The child
receives `RDD_FACTORY_CONTEXT_PATH` and `RDD_FACTORY_CONTEXT_SHA256`; a producing
adapter must read that file and carry its applicable content into its work.
Availability of those bytes does not prove the adapter followed the method.
Inspect the output and reconcile target
effects before reuse, acceptance or settlement. The CLI's `--help` and installed
runtime define the request fields; none of these receipts invent a domain oracle.

On resume, use the same journal and root. On correction, bind the exact new native
turn with `expected_revision`, retain the complete task and relevant materials,
then compile again before dependent work. Do not silently reset resource limits.

Select the task class through `scripts/factory_procedures.py`. Read the selected
ordered original source files and effective adaptations. Feed their relevant
conditions, roles and outputs into the actual assignment. A source-selection
receipt is not proof the procedure was applied. Generation, maintenance, product
fix, live forensics and captured-trace diagnosis have different write authority
and outcomes; diagnosis does not authorize a repair. Upstream model defaults or
messaging suggestions do not override the current user's settings or authority.

## Research toward a decision

Open a bounded episode when a consequential choice, contradiction, changed input,
failure, missing control or promising different framing can change the next
action. Reuse current evidence first. Name the decision, alternatives, access,
counterlead, smallest useful discriminator and consuming operation. Inspect
primary GitHub/source mechanisms and failure behavior, not only descriptions.
Preserve distinct properties before grouping overlapping references.

Reserve every child, retry, acquisition, audit and repair from the same root
allocation. Resume does not replenish it; unknown expenditure remains reserved
until reconciled. Where the native host is outside the owned runtime, the bound
is advisory and must be reported that way. Do not claim that every inference or
side effect is intercepted. A retained frontier need not continually spend money.
Run background research only within authorized bounded work or a requested
schedule. No installation implies a new unattended recurring automation.

Close each episode with actual inspected evidence and a decision consumer:
adopt, confirm, reject for scope, defer or inaccessible. Children represent new
uncertainties, not paraphrases. Retain small distinctions with conditions and
revisit triggers; investigate them when they can alter a decision. Convergent
search stops when additional evidence is unlikely to change the next action.
An adopted finding with no effect on selection, input, code, asset, control or
check remains an execution gap. Research results are evidence, not tool authority.

## Apply a source-backed mechanism

Prefer native capability, unchanged licensed reuse, pinned fork, coherent source
closure and narrow adapter before independent implementation. Preserve exact
source versions, licenses, dependencies, defaults, error/cancellation semantics,
tests and conditional specialist behavior. A clean-room implementation uses the
separate verified access-boundary module; a fresh chat alone is not isolation.

Existing `workflow.py` compiles scoped decisions, transfers, corrections, input
fingerprints and blockers. Use its packet as actual producing input, not a note
beside a different prompt. The owned factory path binds that exact input and
selected closure to the current revision. Key applied transfer instances by
source property/conditions, operation and output; plural lists are not positional
joins. The resulting check must distinguish a plausible implementation which
ignored that property. Source hashes establish identity, not semantic correctness.

Choose an existing qualified host executor for scoped work. Native tools remain
usable without an experimental parallel controller. Missing runtime, platform,
oracle or entitlement is a scoped capability gap: acquire/qualify it within the
task allowance or report the remaining full-scope obligation. Do not relabel
untested adapters as ready, bypass permissions, change the current model or
pretend task receipts commit-fence uncontrolled external systems.

## Make the project operable and inspect the result

Use [project controls](project-controls.md) to inspect the repository and generate
a project-owned control manifest from actual commands and feature facts. A cold
consumer must launch, doctor, drive, inspect durable state and clean owned
resources using that output and project. Reconcile all requested features and
entry/default variants after churn. One control proof is not complete product
acceptance. Keep one live owner for a shared instance; parallel source reading
does not require parallel UI driving. A healthy process with a wedged UI needs
permitted reset/relaunch and a fresh doctor observation before another action.

Keep feature boundaries, authoritative schemas/runtime parsers, shared tokens and
their consumers, effective diagnostics/valid exceptions and usable previews
where relevant. Feature-private duplication can be correct. Shared invariant
changes require checks in affected consumers. Maintenance distinguishes clean,
changed and blocked; it cannot patch product code or expected behavior to hide a
regression. Preserve failure evidence and clean only owned resources.

For UI, use [UI continuity](ui-continuity.md): inspected shipped references,
actual uploaded pixels, image-led ideation with room for composition, precise
font/density/component anchors, fresh critique and comparison of real rendered
states. Preserve the configured Geist and Hugeicons defaults. For reconstruction,
read the existing pipeline and platform modules; observe original state, reset,
ABI/runtime/service boundaries and independent behavior. Generic record checks
cannot establish sensory quality, arbitrary app equivalence or physical behavior.

Bind acceptance to the current complete requirement denominator and exact
candidate, sources, composition, driver and oracle. Fresh checks remain necessary
after reusable actions; cached navigation is not a cached assertion. A builder's
claim, self-comparison, successful compilation or fixture-only check cannot stand
in for independent behavior. Preserve original failed results and independently
reviewed grader amendments. Never improve a score by reducing the requested scope.

## Correct, reconcile, resume and deliver

Persist corrections through the owned gate before admitting dependent work. Mark
stale relevance separately from producer/descendant liveness and target effects.
A stopped process does not prove no effect; a lost reply does not prove failure.
Reconcile actual target state before retry. Rebase only with evidence that the
required obligations and relevant dependency generations are still satisfied;
unknown generations require fresh binding and checks.

Identify processes by actual attempt/start identity, not a PID or branch name
alone. Preserve immutable source commit/tree, expected target base and final
integration commit/tree and retain recovery refs until the durable receipt. Keep
original evidence reachable for resumed consumers. Missing material is an explicit
recovery gap, not a complete import. Imported origin identity conflicts must not
silently overwrite history. Unowned host operations remain outside mechanical
factory guarantees.

Finalize delivery under the same owned correction/integration gate as its current
acceptance comparison. Use the actual artifact, normal entry/default environment
and fresh demonstration. A correction between checking and recording delivery
requires recomputation. Externally mutable targets retain a snapshot/consistency
limit. Deliver useful results and material limits in the native chat; external
publication is a separate authorized action.

Join all recorded attempts and failures to the original task. Distinguish cash,
native subscription quota, API list-price proxy, elapsed time and unknown capture
boundaries. Incomplete census gives a supported subtotal and no whole-task
savings claim. Functional construction checks precede one later frozen complete
comparative campaign; source popularity, cheaper subtasks and audit agreement
cannot establish faster, cheaper or higher-fidelity complete results.

Installation/update uses the repository's reversible release installer. Keep
active/resumable tasks pinned to their actual release path, preserve personal
content outside immutable roots, and check source/discovery/state compatibility
before activation or rollback. Read the installation doctor output's support
scope. Installed, discovered, invoked, applied and independently accepted remain
separate evidence states.

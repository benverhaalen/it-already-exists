# Conditional reverse-engineering reference catalog

Historical source audit as of September 30, 2026, performed October 4. These are inspected mechanisms and scoped limitations, not installed dependencies or an executed universal pipeline. Refresh exact revisions, availability, licenses, and claims before adoption. Keep private target evidence elsewhere. Strict clean-room use requires analyst-side inspection and a reviewed export, not implementer access to reference sources.

Search this catalog for the unresolved mechanism before loading a section: framework/static triage; engine/bytecode recovery; bounded queries and persistent evidence; runtime discovery/replay; active state learning and counterexamples; protocol testing; visual comparison; continuous dynamics; clean-room provenance; System One ranking/routing and calibration. Select by property and domain fit, preserve alternatives, and qualify the resulting interaction. Public source availability is not necessarily an OSS license.

## 2. OSS and research mechanisms worth combining

### Static triage and evidence recovery

**Android reverse-engineering skill — Apache-2.0.** Its useful ordering is framework/HTTP-stack identification before expensive decompilation, then narrow API/call-flow queries and optional second-decompiler inspection. The September snapshot supports split-package inspection. This prevents spending Java-analysis effort on a predominantly Dart, Hermes, or native payload. However, detection is a heuristic: embedded SDKs and mixed-framework packages require inspection of multiple components. [Pinned source](https://github.com/SimoneAvogadro/android-reverse-engineering-skill/tree/04fe39c7dcc8efa0ce39a331862fb76407d2d9dd).

Source audit found a consequential overclaim: its Kotlin name-recovery script treats the first non-framework class reference in `@Metadata.d2` as the owning class name. A small synthetic fixture reproduced a dependency being labeled as the recovered owner. Its claim that Kotlin metadata cannot be stripped is also too broad: shrinkers can remove or rewrite metadata. Treat recovered aliases as hypotheses with provenance. [Script](https://github.com/SimoneAvogadro/android-reverse-engineering-skill/blob/04fe39c7dcc8efa0ce39a331862fb76407d2d9dd/plugins/android-reverse-engineering/skills/android-reverse-engineering/scripts/recover-kotlin-names.sh), [Guardsquare metadata documentation](https://www.guardsquare.com/manual/languages/kotlin).

**JADX — Apache-2.0.** Useful for DEX structure, resources, xrefs, selective class/method inspection, Kotlin metadata support, and alternative decompilation modes. It explicitly does not promise complete decompilation. Keep raw bytecode/smali and unresolved regions available; compare representations on disputed logic. September pin: `2270f9d24d41ddf21e7b9673c9ae0625b8c66db7`. [Repository snapshot](https://github.com/skylot/jadx/tree/2270f9d24d41ddf21e7b9673c9ae0625b8c66db7).

**Blutter — MIT; reFlutter — GPL-3.0.** Blutter provides Dart AOT assembly/object-pool/symbol information and Frida scaffolding. It selects and builds a matching Dart runtime version when needed, making runtime/version caching important. reFlutter supplies modified Flutter libraries for runtime observation. These are framework-specific evidence tools; names, strings, and hooks do not recover every reachable state. Compare patched observations against an unmodified baseline. [Blutter September snapshot](https://github.com/worawit/blutter/tree/4a60ac648bf448c5a7596437243bcd0b9376fdf0), [reFlutter September snapshot](https://github.com/Impact-I/reFlutter/tree/1b5d688ffc00896d3c466797913a99fc846e4d38).

**GlassWing — Apache-2.0 declared.** It addresses a real blind spot: Dart-to-Java/Kotlin platform-channel calls missing from conventional Android graphs. Its artifact combines patched Blutter, intermediate processing, and Soot/FlowDroid-oriented analysis. Transfer the cross-language boundary mapping when behavior crosses Flutter/native code. The repository exposes the Python orchestrator and patched Blutter, but its main analysis components include a JAR/native executable; a complete source rebuild was not verified. Its leak/call-graph results measure security-analysis improvement rather than reconstruction fidelity. [Artifact](https://github.com/glasswing-ase25/GlassWing/tree/59b91b8b66339324655a04a147002f354929d1b8), [primary paper](https://sen-chen.github.io/img_cs/pdf/ASE2025-GlassWing%20A%20Tailored%20Static%20Analysis%20Approach%20for%20Flutter%20Android%20Apps.pdf).

**MobSF — GPL-3.0.** A useful broad static/dynamic security-analysis substrate and triage alternative, particularly for permissions, components, endpoints, and instrumentation. Its security focus does not supply product semantics or complete navigation coverage. Use it when those outputs answer a current uncertainty; avoid making its complete report mandatory for every small feature. [September snapshot](https://github.com/MobSF/Mobile-Security-Framework-MobSF/tree/7a4785fb3b55949231dd2b5d7df82ccba02a114f).

### Engine and bytecode recovery: label what is actually restored

**Il2CppDumper — MIT; Cpp2IL — MIT; AssetRipper — GPL-3.0.** These recover different layers of Unity applications. Dumper restores metadata/schema and native mappings; its generated method bodies return defaults. September Cpp2IL attempts actual instruction-to-CIL recovery, but can emit stubs/throwing methods, and its success counter includes an empty-instruction stub path. AssetRipper recovers assets, scenes, dependencies, and an importable project; its default IL2CPP output has empty methods. Its inspected public Level3 path also falls back to stubs without an injected recovery output. Neither a method count nor an editor-importable project proves restored behavior. Track each method as metadata-only, stubbed, failed, recovered-unvalidated, or differential-tested. Use assets/schema to narrow the remaining investigation and analyze only critical native methods. [Dumper generator](https://github.com/Perfare/Il2CppDumper/blob/4741d46ba9cd6159c5d853eb9d6fc48b4bfa2b1a/Il2CppDumper/Utils/DummyAssemblyGenerator.cs#L254), [September Cpp2IL output](https://github.com/SamboyCoding/Cpp2IL/blob/b5ad444b82267cb1e4b88b8b373c008105bdea52/Cpp2IL.Core/OutputFormats/AsmResolverDllOutputFormatIlRecovery.cs#L37), [September AssetRipper manager](https://github.com/AssetRipper/AssetRipper/blob/813fed1597bac674def7256ce633a227e7b27497/Source/AssetRipper.Import/Structure/Assembly/Managers/IL2CppManager.cs#L98).

**hermes_rs — MIT declared; hermes-dec — AGPL-3.0.** React Native may contain ordinary JavaScript or Hermes bytecode. These tools expose function/module/string tables and disassembly, reducing irrelevant context. The inspected hermes_rs declares selected formats through HBC96 and does not provide its planned functional decompiler; August hermes-dec parses through HBC99 but explicitly emits pseudocode rather than generally valid JavaScript. Check actual payload format first, then correlate async/native bridges with runtime evidence. [hermes_rs snapshot](https://github.com/Pilfer/hermes_rs/tree/c65ba858905411fa35a7d92ddd728ad2d71fa6e6), [hermes-dec snapshot](https://github.com/P1sec/hermes-dec/tree/a0f18f97ab661eb8ed659c8c683a0d21ea619e69).

### Narrow analysis tools and persistent evidence

**ReVa — Apache-2.0.** Its Ghidra tools return structured signatures/xrefs, ranged decompilation, and P-code data-flow slices. Actual implementations cap callers/callees at 50 with limit metadata and cap slices at 500 nodes. This is a strong mechanism for asking “what can write this value?” without sending the entire binary to a model. A truncated result must remain visibly incomplete, and a slice inherits weaknesses in Ghidra's recovered IR. [Decompiler implementation](https://github.com/cyberkaida/reverse-engineering-assistant/blob/01a154a8edf233b02a0e7707e2ff5933893c6d53/src/main/java/reva/tools/decompiler/DecompilerToolProvider.java), [data-flow implementation](https://github.com/cyberkaida/reverse-engineering-assistant/blob/01a154a8edf233b02a0e7707e2ff5933893c6d53/src/main/java/reva/tools/dataflow/DataFlowToolProvider.java). Reviewed September 29 repository state; source links are pinned.

**Cellebrite ghidra-rpc — MIT declared.** A persistent PyGhidra daemon keeps a binary/project loaded across JSON queries. Import once, query many times, and persist edits. This attacks analysis startup overhead directly. Locking, heap requirements, project identity, restart behavior, and cache invalidation remain integration work. [Repository](https://github.com/cellebrite-labs/ghidra-rpc/tree/5b5cb7ba4666215122718ce1ac5a1299ea3db722), reviewed September state.

**GhidrAssist — MIT.** The inspected indexer extracts deterministic structure before optional LLM summaries. This supports demand-driven summaries instead of paying to summarize every function. Its “semantic” search implementation uses full-text search; do not infer embeddings from the GraphRAG name. Its capped findings cache uses security-keyword ranking, which could discard mundane UI/persistence evidence important to reconstruction. Adapt ranking to the user journey and retain raw evidence. [Indexer](https://github.com/symgraph/GhidrAssist/blob/db0bb3da678adb453a499a13feea8ed659102bcb/src/main/java/ghidrassist/graphrag/extraction/BackgroundIndexer.java), [retrieval](https://github.com/symgraph/GhidrAssist/blob/db0bb3da678adb453a499a13feea8ed659102bcb/src/main/java/ghidrassist/graphrag/GraphRAGEngine.java), [cache](https://github.com/symgraph/GhidrAssist/blob/db0bb3da678adb453a499a13feea8ed659102bcb/src/main/java/ghidrassist/agent/react/FindingsCache.java). Reviewed state last pushed September 20.

**Joern + joern-agent-bridge — Apache-2.0.** Code-property graphs provide bounded reachability/control/data-flow queries. The September bridge has allowlisted queries, output/timeout limits, structured metadata, and source/tool/configuration-keyed caches. Useful when source or decompiled code parses reliably. The adapter's tested automatic language paths do not establish equally tested binary support; reflection, native boundaries, and unresolved indirect calls remain gaps. [Bridge query code](https://github.com/epi13/joern-agent-bridge/blob/291fac3cbe7d529066e4f98a02696da71af6575d/src/joern_agent_bridge/query.py), [cache code](https://github.com/epi13/joern-agent-bridge/blob/291fac3cbe7d529066e4f98a02696da71af6575d/src/joern_agent_bridge/workspace.py), [Joern](https://github.com/joernio/joern). Joern's October HEAD was excluded from claims about September capabilities.

**Serena — LSP component MIT, application GPL-3.0-or-later.** Symbol overviews, references, and bounded body retrieval reduce source-context noise. Useful after rebuilding parseable code; a poor fit for arbitrary pseudo-C or stripped binaries. Its own agent evaluations do not establish reverse-engineering accuracy. [Symbol tools](https://github.com/oraios/serena/blob/d0f7f92631c23dc4c5ed0b5ccd35bc623b19a809/src/serena/tools/symbol_tools.py), reviewed September 30 state.

**Cerberus RE — Apache-2.0.** The August snapshot offers Apple binary/static/runtime correlation, function dossiers, durable session material, and an immutable dependency/contradiction evidence graph. These are useful long-running investigation mechanisms. Its benchmark suite is explicitly a scaffold rather than published comparative results. Its evidence certification checks graph integrity and required fields; it does not establish the semantic truth of a claim merely because `verification_path` is nonempty. Add actual artifact rehashing, evidence resolution, and executable behavior checks. [Pinned repository](https://github.com/OwenPawl/cerberus-re-skill/tree/3116c94de17386d18367ed14e55dd2c7d1c7fe14), [evidence code](https://github.com/OwenPawl/cerberus-re-skill/blob/3116c94de17386d18367ed14e55dd2c7d1c7fe14/cerberus_re_skill/modules/evidence_graph.py).

### Runtime discovery, navigation, and cheaper repeated execution

**DroidBot — MIT.** Its UI transition graph, unexplored-action selection, shortest paths, and saved observations provide inexpensive breadth without an LLM per tap. Structural states are navigation clusters, not proven behavioral equivalence: inspected state hashes use a set of view signatures and discard positions, multiplicity, and long text. Retain raw observations and split clusters when future outcomes differ. [September graph/state implementation](https://github.com/honeynet/droidbot/tree/cc4cc93cc539).

**Mobilerun, formerly Droidrun — MIT.** The September 30 snapshot includes useful guarded macro replay and agent fallback. But its default matcher can accept identical nodes with the wrong package/activity, assigns perfect node similarity to empty trees, and omits bounds while replay uses recorded coordinates. Borrow the reuse mechanism with stronger preconditions, target reacquisition, and postconditions. These risks follow from source; they were not demonstrated on a device in this investigation. [Matcher](https://github.com/droidrun/mobilerun/blob/8944aa1dd118/mobilerun/macro/matcher.py), [replay](https://github.com/droidrun/mobilerun/blob/8944aa1dd118/mobilerun/macro/replay.py).

**MobiAgent — Apache-2.0 repository.** AgentRR caches task/action routes with exact/fuzzy retrieval and target-change checks. July 2026 releases add on-device inference and a quantized 2B model. Repeated stable routes are the natural workload; embedding/reranker preparation, local hardware, and cold-start costs must be included. Source treats a missing screenshot/target as unchanged, so the proposed integration must reject missing evidence instead. [September snapshot](https://github.com/IPADS-SAI/MobiAgent/tree/4ee794021bb34a8de4d00c52ca8fa6f0065a45ff), [cache implementation](https://github.com/IPADS-SAI/MobiAgent/blob/4ee794021bb34a8de4d00c52ca8fa6f0065a45ff/agent_rr/action_cache/tree.py).

**AppAgent — MIT.** Exploration/demonstration creates reusable element-action documentation; useful as a runtime knowledge-acquisition pattern. Before/after reflection adds model calls, and documentation from one interaction may omit history-dependent behavior. Store condition/action/outcome evidence rather than universal prose descriptions. [Explorer](https://github.com/TencentQQGYLab/AppAgent/blob/2c1900422caf6f9e94e96d5dd984b530e5a5fbf8/scripts/self_explorer.py).

**Mobile-Agent v3.5 / GUI-Owl 1.5, UI-TARS 1.5, Agent S3.** Modern GUI grounding/planning can reach forms and deep workflows that inexpensive exploration misses. Mobile-Agent's reviewed deployment path is Android, even where model claims are broader. UI-TARS grounding and AndroidWorld task scores evaluate different abilities. Agent S3 removes hierarchy, bounds image history, and makes reflection optional: a useful counterexample to assuming more roles always improve efficiency. Best-of-N selection trades additional rollouts for success. Repository licenses are MIT for Mobile-Agent and Apache-2.0 for UI-TARS/Agent S; model/checkpoint terms require separate checks. [Mobile-Agent](https://github.com/X-PLUG/MobileAgent/tree/11cea575561f/Mobile-Agent-v3.5), [UI-TARS](https://github.com/bytedance/UI-TARS/tree/582f3a7ea5d2), [Agent S3](https://github.com/simular-ai/Agent-S/tree/3aa272d23d29).

**OmniParser.** OCR, icon detection/captioning, and boxes help custom interfaces with weak semantic trees. Vision outputs are predictions to test through interaction. The inspected repository LICENSE is CC-BY-4.0 despite a differing README badge; detector/model terms differ by version, including older AGPL detectors. Pin code and weights separately. [September snapshot](https://github.com/microsoft/OmniParser/tree/354021201345).

**Kea — MIT; Kea2 and Fastbot — restrictive current licenses.** Conditional exploration scripts and precondition/scenario/assertion rules reach deep states and detect noncrashing errors. Kea2's FSE 2026 approach combines Fastbot 3.0 with small Python guidance rules. Transfer that mechanism; do not call all public repositories freely distributable OSS. Original Kea is a clearer reusable base. [Kea](https://github.com/ecnusse/Kea/tree/28b0b41249c5), [Kea2](https://github.com/ecnusse/Kea2/tree/a294f566527aacf629a0793c53e70fb020824d0e), [Fastbot](https://github.com/bytedance/Fastbot_Android/tree/d057b99115ca).

**AndroidWorld — Apache-2.0.** Its initialize/evaluate hooks and actual saved-state rewards supply a valuable evaluation pattern. Its 116 tasks across 20 apps measure task accomplishment, not complete specification discovery or original/rebuild agreement. [September snapshot](https://github.com/google-research/android_world/tree/2655e27cd090).

### Behavioral learning, testing, and counterexample-driven repair

**AALpy — MIT declared; LearnLib — Apache-2.0.** Active automata learning asks action sequences, proposes a finite-state model, searches for a contradicting sequence, and refines. Crucially, future action suffixes distinguish states that look identical now. Query caches and LearnLib state reuse reduce repeated reset/navigation. W-method tests can grow exponentially with alphabet and state bound; use small feature models and bounded conformance tests. Repeated conflicting outputs require investigating resets/nondeterminism rather than hiding discrepancies. [AALpy cache/reset](https://github.com/DES-Lab/AALpy/blob/655032ca46ad0ea43a7854fb4d55eda4cfbb10e0/aalpy/base/SUL.py), [W-method](https://github.com/DES-Lab/AALpy/blob/655032ca46ad0ea43a7854fb4d55eda4cfbb10e0/aalpy/oracles/WMethodEqOracle.py), [LearnLib reuse](https://github.com/LearnLib/learnlib/blob/3670e72d14f6641c266b236b77c7a4d3c27a5b35/filters/reuse/src/main/java/de/learnlib/filter/reuse/ReuseOracle.java).

**Hypothesis — MPL-2.0 with component exceptions.** Stateful rules generate dependent action sequences and shrink failures to small examples. Drive original and reconstruction through the same semantic sequence with platform-specific action adapters. A shrunk “change preference → cancel → relaunch” discrepancy is far more useful model input than a long failed session. Flaky resets and loose normalizers can undermine the result. [September stateful documentation](https://github.com/HypothesisWorks/hypothesis/blob/44b82b24cb40c72afd1f6e10c2af7a5d82c6539a/hypothesis/docs/stateful.rst).

**mitmproxy, mitmproxy2swagger, Schemathesis — MIT or MIT declared.** Capture/replay traffic; infer a provisional OpenAPI surface; use producer/consumer relationships to generate stateful API sequences. Captured traffic is a sample, not the server specification. mitmproxy's inspected client replay rejects WebSocket flows; unusual protocols and pinning require a different capture path. Schemathesis needs valid links/seeds and custom business assertions to establish equivalence. [Replay implementation](https://github.com/mitmproxy/mitmproxy/blob/6a209f74406ecf96bc2e3cec877250539430427a/mitmproxy/addons/clientplayback.py), [schema extraction](https://github.com/alufers/mitmproxy2swagger/blob/f432acafa5907258f0f529ff582c75fefdca00d7/README.md), [stateful testing](https://github.com/schemathesis/schemathesis/blob/92c85309625bfde86ed13aed9a05c9be389d3e01/docs/explanations/stateful.md).

**pixelmatch — ISC.** Its September implementation uses OKLab/HyAB comparison and localized windows to reduce scattered rendering noise dominating compact regressions. Calibrate against original-versus-original variation and seeded UI errors; compare semantics, timing, and state separately. [September implementation](https://github.com/mapbox/pixelmatch/blob/b2800051f2b79d18cf27e51cd240cafd38cfb0ba/index.js).

**CHISEL — August 2026 public research source; no license found.** Its important mechanism is compact compiler/fuzzing feedback, cross-iteration divergence memory, and best-candidate retention. The paper evaluates 120 x86-64 functions; it reports 79.8% average reexecution, with materially weaker stripped-binary results and nonzero false acceptance. This is not whole-app recovery. Critically, inspected code compiles the reference from dataset source (`record['func_def']`), so an arbitrary original-binary harness remains work to do. Borrow ideas with appropriate rights and a trusted runtime oracle. [Paper](https://arxiv.org/abs/2608.27981v1), [source at inspected commit](https://github.com/VarunKohli18/chisel/blob/76c87a7216409963085f04b059affab00e6453d2/decomp/fuzz.py).

**LLM4Decompile / SK2Decompile — MIT code, separate model terms.** Separating structure/types from later name restoration is useful. Its Linux x86-64 GCC benchmark scope does not establish Android ARM64, Swift, or Dart fidelity. A local specialist is a candidate for inexpensive hypotheses after an applicability test, not a default acceptance oracle. [Repository](https://github.com/albertan017/LLM4Decompile).

**D-Helix — BSD-3-Clause.** Symbolic differentiation can expose errors that finite fuzzing misses and diagnose decompiler heuristics. Its patched/pinned research environment and solver path explosion make it a targeted option for a bounded important numerical/protocol function. [Repository](https://github.com/purseclab/D-helix).

**PANDA — GPLv2 with component terms; rr — MIT-style core with exceptions.** Record once and run later analyses can reduce repeated difficult navigation and support dynamic causality/taint investigations. Environment fit is decisive: neither is a universal recorder for modern iOS/Android GPU applications. rr supports some AArch64 configurations; treating it as x86-only would be outdated. PANDA replay support differs by guest architecture. [PANDA September snapshot](https://github.com/panda-re/panda/tree/36502113107ff260e7499065c9d4b764d387a7da), [rr](https://github.com/rr-debugger/rr/tree/179bbce14f483bf3978d00695c1f6ee5827acb67).

**PySINDy — MIT.** Continuous behavior can be investigated as system identification: collect controlled trajectories, fit parsimonious dynamics, and validate unseen inputs. Weak/integral formulations help derivative noise. Hidden state, perspective projection, collisions, RNG, and mode switches can defeat smooth equations. Use piecewise event/dynamics models where needed. [Practical limits](https://github.com/dynamicslab/pysindy/blob/c4421fcec275c8f4cc5c1e93bebb961b212067ae/docs/tips.rst).



## 6. Clean-room reconstruction and OSS evidence

Clean-room independence and behavioral fidelity are separate objectives. A rewrite can be independent and inaccurate; a highly compatible replacement can knowingly reuse licensed source. Choose the permitted evidence and intended license/provenance route before analysis. If compatible OSS reuse meets the objective, adapting it with the required attribution can avoid the substantial cost of rediscovery. A formal independent implementation requires an information barrier; changing names or paraphrasing source does not establish one.

The useful examples are broader than repositories that advertise “clean room”:

| Project | Mechanism worth transferring | What the evidence does not establish |
|---|---|---|
| ReactOS | Explicit source-exposure policy, subsystem provenance, documentation-to-implementer separation and historical audit. | A uniform process for every contributor/component or complete compatibility. |
| Wine | Observable behavior encoded in compatibility tests: return values, errors, effects and quirks; known divergences remain marked. | Whole-program equivalence or permission to reuse all other projects' reverse-engineered material. |
| Samba | Modify protocol negotiations between native implementations to expose otherwise hidden branches. | A two-team clean-room barrier across all components. |
| Nouveau | Timestamped reads/writes at the device-driver boundary, marked experiments and narrow interface traces. | Complete traces on every platform or zero instrumentation perturbation. |
| OpenMW | Independently written engine, documented formats, separate user-provided original assets. | A documented formal barrier for every contributor or completed game parity. |
| OpenRA / ScummVM | Successful recreation architecture and long-term compatibility work. | Uniform strict clean-room methods: OpenRA has learned from released original source; ScummVM combines reverse engineering and rightsholder source grants. |

Primary sources: [ReactOS participation](https://reactos.org/participation/), [ReactOS historical audit](https://reactos.org/project-news/reset-reboot-restart-legal-issues-and-long-road-03/), [Wine file tests](https://github.com/wine-mirror/wine/blob/6d1b09405774c4f234ed3fa0088a9706deb7ad49/dlls/kernel32/tests/file.c), [Samba protocol intervention](https://lists.samba.org/archive/samba-technical/2003-January/026382.html), [Nouveau tracing](https://nouveau.freedesktop.org/MmioTrace.html), [OpenMW FAQ](https://openmw.org/faq/), [OpenRA source-informed development](https://www.openra.net/news/devblog-20200629/), [ScummVM historical FAQ](https://www.scummvm.org/old/faq.php). Wine's policy wiki was inaccessible on this research pass; its precise current wording is not asserted. Importing existing test code also requires observing that code's license.

**whit3rabbit/clean-room-skill — MIT, August 4 cutoff snapshot.** This is the most directly applicable modern process scaffold found. It separates source-reading analysis, a source-denied handoff sanitizer, and fresh planner/implementation contexts. It provides schemas, coverage/evidence ledgers, approved behavioral handoffs, hash checks, leakage scanners, access hooks and tests for path traversal and prohibited artifacts. These mechanisms make the boundary inspectable and resumable. [Pinned repository](https://github.com/whit3rabbit/clean-room-skill/tree/1c6a6b7cf7a7596ea58ae807567f8a8dcf09e4ff), [architecture](https://github.com/whit3rabbit/clean-room-skill/blob/1c6a6b7cf7a7596ea58ae807567f8a8dcf09e4ff/docs/ARCHITECTURE.md).

Its actual runner launches ordinary subprocesses with bounded inputs, role-specific working directories and environments; fresh Claude sessions use `--no-session-persistence`. That code does not itself create a kernel filesystem sandbox. Hook enforcement requires the host to emit covered tool events. The stored sanitizer evaluation and boundary tests are useful narrow evidence, not a demonstrated automatic whole-app recreation. Add actual filesystem isolation and test every enabled access channel before relying on strict separation. [Runner](https://github.com/whit3rabbit/clean-room-skill/blob/1c6a6b7cf7a7596ea58ae807567f8a8dcf09e4ff/lib/run-stages.cjs), [read policy](https://github.com/whit3rabbit/clean-room-skill/blob/1c6a6b7cf7a7596ea58ae807567f8a8dcf09e4ff/hooks/deny-clean-source-read.py), [boundary tests](https://github.com/whit3rabbit/clean-room-skill/blob/1c6a6b7cf7a7596ea58ae807567f8a8dcf09e4ff/tests/hook-access-policy.test.js).

**Zxs — BSD-3-Clause, February 2026.** Its author describes a Claude-generated Z80 core based on hardware documentation without consulting other emulator source. Actual tests cover instruction effects, flags, prefixes and cycle counts. It is a useful bounded documentation-to-implementation example, with a much more precise starting specification than an opaque app. I inspected its tests but did not rerun them or establish complete hardware equivalence. [Snapshot and tests](https://github.com/ajokela/zxs/tree/5c34e4ba7e7eadd0fa435c66b8ee3848dc3cc448).

For this reconstruction process, the recommended boundary is:

1. **Observation domain:** original binaries/source, decompilation, raw traces, source-informed hypotheses and analyst retrieval indexes.
2. **Reviewed handoff:** observable inputs/outputs, state transitions, timing tolerances, independent test vectors, approved public compatibility identifiers and unresolved behavior. Keep provenance in the analyst ledger; do not erase it to make evidence appear independent.
3. **Implementation domain:** fresh agent history, approved specification, independent dependencies and tests. Exclude original source mounts, analyst chat, shared memories and source-informed RAG. If using this conversation for future implementation, retain it on the analyst side and launch a separate implementer.
4. **Oracle feedback:** sanitized behavioral counterexamples such as “after A then B, C must persist,” rather than target helper names, branches or translated pseudocode.
5. **Boundary verification:** prohibited canaries tested through search, symlinks, shell, MCP/resources, browser and build tools, with denial receipts and access logs. Hashes prove artifact identity; they do not prove the specification is free of copied expression.

This adds sanitation, handoff and repeated-query costs. Batch coherent behavioral slices to limit duplicated discovery. Session isolation records supplied information; it cannot certify unknown model-training provenance. This is an engineering provenance proposal, not a determination of legal clearance. [ReactOS IP guidance](https://reactos.org/intellectual-property-guideline/), [US Copyright Office computer-program guidance](https://www.copyright.gov/register/tx-programs.html).

## 7. Are System One models useful here?

**Yes, conditionally, for repeated bounded semantic decisions.** The useful architectural idea is to compute a typed judgment over a supplied state without generating an explanation at every step. Jev's Choice/Noul/Score primitives select from candidates, judge a condition or rate an ordinal scale; they do not generate source code or directly process screenshots. A classifier, encoder or one-pass option scorer can implement a similar narrow role. Deterministic parsers and validators remain preferable for facts already measurable in code. [TypeSafe model contract](https://docs.typesafe.ai/concepts/system-one).

### Evidence of working mechanisms, with scope preserved

**AppliedMachineLearning-Lab/jev-benchmarking — MIT code, September 30 snapshot.** This independent harness is stronger evidence than a showcase: it ships dataset/question definitions, exact-request caches, development-only threshold tuning, evaluation code and per-dataset results for `jev-1.13.0`. Authors report 346,009 evaluation requests across 37 benchmark tasks for $9.15 and about 5h15m; these are recorded costs for that run, not a current price guarantee or RE cost forecast. [Pinned harness](https://github.com/AppliedMachineLearning-Lab/jev-benchmarking/tree/6bbdeb33474849b6de2f0cccc9f5e19756abd67e), [run ledger/methodology](https://github.com/AppliedMachineLearning-Lab/jev-benchmarking/blob/6bbdeb33474849b6de2f0cccc9f5e19756abd67e/docs/datasets.md).

The shipped results include approximately **89.5% CLINC intent classification**, **79.7% Banking77 classification**, **78.6% mean balanced accuracy on LLM-AggreFact grounding**, and **0.89 Spearman on STS-B similarity**. These support using fast decisions for candidate routing, evidence ranking and preliminary claim checks. They also show why none should become an unquestioned oracle: errors remain material, tasks differ, and intent labels are not reconstruction-tool labels. Public benchmark exposure can remain unresolved even after option-rotation controls. The audit excludes arithmetic/code tasks from its BIG-bench subset, so its averages do not establish general reasoning capability. [Intent results](https://github.com/AppliedMachineLearning-Lab/jev-benchmarking/blob/6bbdeb33474849b6de2f0cccc9f5e19756abd67e/results/eval/clinc150.json), [grounding results](https://github.com/AppliedMachineLearning-Lab/jev-benchmarking/blob/6bbdeb33474849b6de2f0cccc9f5e19756abd67e/results/eval/llm_aggrefact.json), [similarity results](https://github.com/AppliedMachineLearning-Lab/jev-benchmarking/blob/6bbdeb33474849b6de2f0cccc9f5e19756abd67e/results/eval/stsb.json).

The important license distinction: **Jev itself is closed**. Its MIT benchmark harness does not make the model OSS. Published Jev response data permits research/evaluation but restricts imitation training and competing-product development; it must not be treated as unrestricted distillation data. Open-model comparison responses have separate terms. [Response license](https://github.com/AppliedMachineLearning-Lab/jev-benchmarking/blob/6bbdeb33474849b6de2f0cccc9f5e19756abd67e/responses/LICENSE_RESPONSES.md).

**TypeSafe's executed retrieval cookbook — vendor demonstration, not an OSS deployment benchmark.** A 40-query CLERC example reranks 30 BM25 candidates per query: reported top-1 retrieval improves from 5% to 18%, top-10 from 38% to 62%, for $0.0645 of recorded calls at August pricing. Transfer the mechanism: first retrieve cheaply, then spend semantic judgment only on a shortlist. It cannot recover a missing candidate. The eight-example citation cookbook combines deterministic quote matching with a supports/contradicts/neither decision; eight crafted examples do not estimate production accuracy. [Retrieval example](https://docs.typesafe.ai/cookbooks/rerank_typesafe), [citation example](https://docs.typesafe.ai/cookbooks/citation_check).

**wfzyx/von — Apache-2.0 code and declared weights, September 30 snapshot.** An actual open alternative: a 395M ModernBERT encoder scores option markers, serves Choice/Noul/Score through a compatible API, exposes calibration and bounded deterministic numeric/date operators. The author reports strong easy-tier performance but much weaker hard/sealed performance; a Doom demo and small agent-triage probes are self-reported illustrations rather than proof of reverse-engineering quality. The repository's statistical gate and openly recorded limitations are more useful than its demo for adoption decisions. [Pinned source/model card](https://github.com/wfzyx/von/tree/8a0bf831f750864b622e14055420df3f77aff606), [inference backend](https://github.com/wfzyx/von/blob/8a0bf831f750864b622e14055420df3f77aff606/src/von/backends/option_marker_backend.py).

A consequential source finding: Von defaults to `band` mode, remapping Noul outputs to commit outside a benchmark's 0.2–0.8 abstention band. This preserves yes/no ordering but changes the reported probability. **Set `VON_NOUL_DECISION=raw` before using probabilities for uncertainty or escalation**, then calibrate on the actual workload. Also use refusal on context overflow; middle truncation can discard a decisive condition. One encoder pass avoids generated tokens, but its compute still scales with input/options; optional chains add passes and latency.

**Two additional public benchmarks illustrate why source audits matter.** `instax-dutta/sysone-bench` (MIT, September 27 snapshot) has frozen manifests and a committed nine-suite report favoring Jev, but AI-drafted labels were corrected by one human without independent adjudication. More seriously, its `_ece` metric omits bin occupancy weighting. I extracted that actual function into a stdlib-only fixture: 100 predictions at confidence 1.0, with 50 correct, produce **0.005**, whereas standard weighted expected calibration error is **0.5**. Its reported calibration conclusions cannot justify an uncertainty gate until corrected and recomputed. This bug alone does not invalidate separately computed accuracy or latency. [Pinned metric](https://github.com/instax-dutta/sysone-bench/blob/9447a17fccb524957d1211ecdf46153821ff0810/benchmark/metrics.py), [label protocol](https://github.com/instax-dutta/sysone-bench/blob/9447a17fccb524957d1211ecdf46153821ff0810/README.md).

`mallahyari/system-one-benchmark` (September 19; no standalone license found) ships a 50-example ToxicChat comparison, but its “one pass” local scoring path actually includes prefix prefill, suffix evaluation and extra continuation passes on token collisions. It can floor collision confidence at 0.70 while always reporting one sequential pass. The README also confuses schema validity with error rate, and toxicity/jailbreak labels do not establish general attack detection. These are public mechanisms to inspect, not evidence for blanket compute, calibration or RE-accuracy claims. [Actual local scorer](https://github.com/mallahyari/system-one-benchmark/blob/46c232b887d41b4b560a1eac74972eade3b1fddc/local_pcd_engine.py).

**RouteLLM — Apache-2.0, established OSS mechanism.** Its matrix-factorization/BERT routers predict whether a stronger model is worth using; the repo supplies threshold calibration and cached MMLU/GSM8K/MT-Bench evaluations. It reports up to 85% cost reduction while retaining 95% of GPT-4 benchmark performance for its studied setup. This is evidence that learned routing can help; it is not a forecast for present models or RE. The **2026 LLMRouterBench** study supplies counterevidence: under unified evaluation, several recent routers fail to reliably beat a simple baseline. Its source is public; a reusable license was not established in the inspected snapshot. Adopt the evaluation method before the router. [RouteLLM snapshot](https://github.com/lm-sys/RouteLLM/tree/0b64fdafe049e596a3f5657c219329f24af24198), [modern routing study](https://arxiv.org/abs/2601.07206v1), [public evaluation artifact](https://github.com/ynulihao/LLMRouterBench/tree/c77cb0506949d8f959e97967d2fefca0e8ff1b05).

RouteLLM's controller routes on only the latest message and explicitly notes first-turn training. Supply a bounded job with its relevant evidence rather than assuming a router sees accumulated RE uncertainty. [Controller](https://github.com/lm-sys/RouteLLM/blob/0b64fdafe049e596a3f5657c219329f24af24198/routellm/controller.py). An advertised clean-room playground likewise does not establish live model success: its browser demos explicitly use simulated Jev decisions and deterministic templates. It was inspected as a present-day claim check, with no September provenance established, and is excluded from the cutoff technology recommendations. [Demo disclosure](https://jev.works/agents/clean-room).

### Where to place fast judgments in the combined process

| Candidate role | Deterministic protection | Adoption criterion |
|---|---|---|
| Rank retrieved functions, traces and prior observations for an unresolved behavior | Preserve original shortlist, evidence IDs and an explicit no-match outcome. | Better held-out evidence recall within the same inspection budget. |
| Classify failure reports into capture/reset, navigation, build, interface or semantic mismatch | Compiler/runtime facts and known exact error patterns run first. | Fewer misrouted failures and less total repair time than rules alone. |
| Suggest whether a specification claim is supported by supplied evidence | Exact quotes/paths/hashes checked in code; disputed claims retain source pointers. | Adjudicated support/contradiction recall, including deliberately unsupported claims. |
| Suggest a tool/model or exploration priority | Allowed-tool policy and budget remain in code; unknown/out-of-scope escalates. | Better fidelity per total dollar/minute than rules, random routing and strongest-model-only. |
| Flag possible source leakage in a clean handoff | Filesystem separation, provenance review and concrete access tests remain mandatory. | Measured detection on planted leakage without blocking necessary public identifiers; never sole certification. |

Do not give this layer final authority over state equivalence, behavioral correctness, numerical physics, clean-room independence or coverage completeness. In particular, semantically similar screen descriptions can still hide different histories. A confident classification is a proposal until the experiment or assertion confirms it.

Evaluate fast judgments on independently labeled reconstruction examples, separating development from held-out cases and including unseen apps, long context, ambiguous labels and contradictions. Freeze the model/prompt/threshold, expose an abstention path, cache exact unchanged questions and batch independent judgments over the same state. Record routing overhead, extra retries and semantic errors, not only generated-token savings. There is no demonstrated end-to-end RE saving from these integrations yet.


## Follow-up: preserving ARM32 logic across instruction sets

October5 source inspection, outside the original September cutoff: a no-JIT
interpreter can preserve existing machine-code semantics while host adapters
replace platform dependencies. Treat CPU execution, ELF loading/relocation,
JNI ABI, synchronization, graphics and device performance as separate claims.

- [touchhle-arm-interpreter](https://github.com/moleworld-dev/touchhle-arm-interpreter/tree/adffbbdae912568557f33f8596110cc677809641), MPL-2.0: inspected Rust ARM/Thumb/VFP interpreter with partial NEON, SVC host boundary and optional target-specific PC hacks disabled by default. Its upstream suite has four basic integration tests and one compile doctest; the extracted differential harness is absent. Actual source uses a single-thread address-only exclusive monitor. Selected native leaf functions were additionally compared against a native oracle on ARM64 host and iOS simulator, but this does not establish full ISA, Android threading or game support. Qualify unsupported instructions and synchronization rather than assuming ARMv7 branding means completeness.
- [lunaria](https://github.com/yui0/lunaria/tree/a40c3d5f88719d9ee37a1c3132b150495b91adfc), MPL-2.0 with retained bionic linker notices: actual ELF relocation cases and JNI/DVM interfaces supply adapter references. Its desktop dynarmic backend is not an iPhone no-JIT implementation. The large execution core was not inspected in this probe; broad coverage and performance claims remain unverified.
- [ZettaBridge](https://github.com/ZailoxTT/ZettaBridge/tree/d6066b9b9e61de27041ba6e1f3c499c080c9e2b7): synthesized guest-width JNI and typed host reflection are useful cross-ABI mechanisms; the inspected Android guest runtime depends on real JNIEnv. Android execution success cannot establish iOS execution, licensing fit or distribution readiness. Check its exact license and component notices before adoption.

Use these as conditional mechanism references, preserving each backend's limits.
An independently called native oracle is stronger than tests authored from the
interpreter implementation; retain original state/output evidence through CPU
acceleration or refactoring. Short leaf throughput cannot predict whole-game FPS.

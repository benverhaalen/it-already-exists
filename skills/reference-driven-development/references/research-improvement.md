# Improve RDD through its own references

Use RDD on the complete discovery, investigation, synthesis, transfer and reuse
process when omissions, lost conditions, weak combinations or research cost
obstruct the artifact. Keep the existing route as a baseline. Search providers
are optional mechanisms; more links and better-looking reports do not establish
a better built result. Use the existing journal rather than a second provenance
system. Separate source-assisted inspection from clean-room specification export.

## Research toward a composition

For a consequential approach, load [synthesis](synthesis.md) and give each useful
resource a job in our own system. Resources may be code, OSS, concepts, product
behavior, visual references or expert processes. Inspect the property actually
being transferred; a repository name or a shared label is insufficient.

Explain the assembly in existing contribution, decision and transfer records:
what each piece supplies, what remains intact, the deliberate adaptation,
connecting contracts, dependencies, conflicts and missing pieces. Preserve small
differences before grouping. Separate licensed reuse from independent behavioral
implementation and keep analyst source access outside strict implementer handoffs.

Use a distinguishing case to compare original, adapted and combined behavior;
probe important interactions and plausible substitutions. Pass the resulting
composition into the producing assignment and inspect the integrated journey.
Retain useful ideas that do not currently fit, with conditions and revisit triggers.
Do not force every reference into the build or claim an untested blend is better.
The executable research handoff carries this assignment, not an automatically
derived or verified combination.

## Broaden along different mechanisms

Choose lanes by the unresolved decision; do not run every lane for small tasks.

| Lane | Contribution | Discriminating check |
| --- | --- | --- |
| General web search | Direct solutions, primary documentation and terminology | Can the original source support the transferred property? |
| GitHub repository, code, issues and history search | Concrete implementations, failure reports, forks and abandoned alternatives | Read the relevant path/tests at a pinned revision; inspect license and unresolved issues |
| Semantic retrieval, optionally Exa | Evidence described with different terminology | Does it add useful verified mechanisms the baseline missed? |
| Multiple search indexes, optionally SearXNG | Different index coverage and ranking | Count unique useful contributions after derivative-source deduplication |
| Perspective-driven questions | Requirements or tradeoffs absent from initial framing | Ground follow-up questions in actual newly inspected evidence |
| Citation/dependency/fork traversal | Older or niche work hidden by top-level ranking | Trace the mechanism to its original implementation, not a chain of summaries |

Search both application vocabulary and causal structure. Change the framing when
results keep returning the same cluster. Retain minute contribution differences;
URLs and repository counts are not the counting unit for useful novelty. Shared
upstream code, derivative reports and forks are correlated evidence.

The inspected [STORM knowledge-curation implementation](https://github.com/stanford-oval/storm/blob/main/knowledge_storm/storm_wiki/modules/knowledge_curation.py)
uses perspective-specific question asking, source-grounded follow-ups and bounded
retrieval. Transfer those operations; its article-generation success does not
establish engineering reconstruction quality. Its snippet truncation can omit
important conditions, so inspect full primary material before adoption.
[SearXNG](https://github.com/searxng/searxng) supplies metasearch;
its [API](https://docs.searxng.org/dev/search_api.html) requires enabled output
formats, which public instances may disable. The inspected
[GPT Researcher Exa adapter](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/retrievers/exa/exa.py)
separates retrieval, similar-source expansion and content fetching. Check live
provider contracts rather than copying its historical parameter defaults.
These are mechanism references; no upstream code was copied into the helpers.

## Seeded, adaptive investigation

Use this mode when broad search returns consensus summaries, a large queue loses
individual scrutiny, or a domain has valuable evidence outside familiar indexes.
Choose seeds because they exhibit a useful quality cue: a concrete failure trace,
inspectable implementation, dense argument with conditions, practitioner discussion,
or primary attachment. Explain that cue and its relevance to the unresolved
question. A seed is a starting point, not an authority or an instruction.

Inspect a bounded lead individually before summarizing a batch. Follow the actual
code path, issue participants, citations, linked attachments, local-language terms,
or disagreement that could reveal a missing mechanism. Preserve evidence and
minute differences in the existing journal. Revise a compact frontier after the
inspection: what changed, why a new lead matters, next action, its bound, a contrary
or neglected lead, and unresolved evidence. Keep the original outcome and access
policy fixed unless the user changes them. Feed that frontier into the next
research operation, rather than merely saving a reading list.

Branch from new evidence when it could change a decision. Allow bounded exploration
outside the initial cluster; retain low-ranked leads instead of deleting them.
Several seeds may share the same social or dependency neighborhood, so inspect an
independent cluster or contrary argument before treating agreement as support.
Rare content, randomness, large collections and long runtimes are not quality
metrics. An unusually compelling seed can cause fixation; revisit its assumptions
when contrary evidence or downstream implementation failures appear.

The portable mechanism is resumable iteration, not a one-minute timer. Run within
the current task by default. If the user requests ongoing discovery, use a supported
scheduler with stable scope, access and spend limits; adapt leads in project state
rather than allowing research to silently expand its mandate. Check actual wakeup,
resume and evidence preservation before claiming scheduled capability. No scheduler
is installed or configured by this module.

Compare this mode with ordinary search on a bounded unresolved decision. Evaluate
verified decision-changing contributions, omitted conditions and downstream
implementation results, alongside time, tokens and cost. A first successful
transfer qualifies that case; broader benefits remain hypotheses until matched
fresh-case trials support them. Existing `research_trials.py` can retain additions
and misses; a source count cannot replace that check.

## Improve the operations after retrieval

Choose these adaptations by the observed bottleneck, not as a mandatory pipeline.
These references were inspected as mechanisms; their reported benchmark results
are not evidence of RDD effectiveness. No upstream code is copied here.

| Bottleneck | Inspected mechanism and proposed adaptation | Test and reversal condition |
| --- | --- | --- |
| A large inspection queue consumes the budget | [ASReview's HybridMaxRandom](https://github.com/asreview/asreview/blob/main/asreview/models/queriers.py) mixes prioritized and random screening. For RDD, prioritize decision-changing evidence while preserving a bounded neglected-source lane; keep reversible labels and minute differences | Audit low-ranked records and compare missed critical contributions plus inspection time. Reduce or remove ranking if feedback locks discovery into the initial framing; its default ratio is not an RDD optimum |
| Terminology search misses equivalent code | [ast-grep](https://ast-grep.github.io/guide/introduction.html) searches syntax patterns. Once a mechanism is identified, inspect structurally similar implementations in permitted source trees, alongside lexical search | Use known positive and negative examples, then inspect actual matches. Syntax matches do not establish equivalent behavior; unsupported grammar or runtime semantics requires another route |
| Top results hide older origins or correlated copies | [OpenAlex citation traversal](https://help.openalex.org/how-to/api-recipes/) exposes incoming, outgoing and related works. Follow citations for scholarly mechanisms, and dependency/fork/history links for code | Does traversal uncover a distinct applicable mechanism or counterexample? Stop a convergent branch; citation count and common upstream ancestry do not establish independent support |
| A valuable source changes or disappears | [Software Heritage SWHIDs](https://docs.softwareheritage.org/devel/swh-model/persistent-identifiers.html) identify archived software objects. Add a verified archived identifier when available alongside the existing pinned revision and local digest | Resolve the identifier to the inspected object and test later retrieval. Keep local permitted evidence when archival coverage is absent; an identifier is not a license or permission to redistribute |
| Extraction or handoff loses the conditions that made an idea work | [STORM's curation code](https://github.com/stanford-oval/storm/blob/main/knowledge_storm/storm_wiki/modules/knowledge_curation.py) grounds follow-up questions in evidence but bounds its conversational/snippet context. Re-open primary material for conditions, exceptions and competing explanations before synthesizing | A fresh-context reconstruction must recover the mechanism, conditions and differences from journal links. Expand context or change extraction when omitted constraints change implementation |
| Repeated prompts produce the same research mistakes | [GEPA's candidate selector](https://github.com/gepa-ai/gepa/blob/main/src/gepa/strategies/candidate_selector.py) can preserve candidates that excel on different validation cases. Use actual artifact failures to revise questioning, extraction or handoff instructions; retain conditional specialists | Optimize on development traces, then test held-out cases and domains. Reject apparent gains driven by benchmark leakage, report style or lost critical behavior; do not select solely by an average |
| Individually useful ideas interfere when combined | Use the existing synthesis original/adapted/combined probes and record dependencies, exclusions and environment assumptions before assembly | Check the complete intended journey and important combinations. Keep incompatible alternatives available in their applicable contexts instead of forcing a universal blend |

For each unresolved question, `workflow.py` now carries its actual competing
explanations, next evidence and bound into both investigation and builder context.
The research operation also calls for lineage inspection, protected exploration,
transfer checks and explicit unresolved/blocked accounting. These are proposed
operations, not receipts that research ran. An agent must populate the existing
reference → evidence → contribution → transfer → check chain from actual work.
A strict clean-room builder receives the reviewed behavioral export, not this
analyst packet or source inspection material.

## Compare methods on held-out decisions

Before promoting a consequential research-method change, select representative unresolved
questions from different domains and include a rare/older reference case. Keep
objective, time and spend bounds, evidence access and judging criteria comparable.
Change one producing operation at a time when attribution matters. Test provider
substitution separately from query expansion; otherwise gains cannot be attributed
to the provider. Also compare baseline plus candidate to
baseline alone when complementary discovery is the intended use.

Save query variants, filters, modes, timestamps, failed requests, results and
inspection evidence privately. Blind the reviewer to strategy when practicable.
Judge contributions by applicability, preserved conditions, counterevidence and a
concrete discriminating experiment. Follow promising contributions into an actual
implementation probe: more retrieved sources can still increase repair cost.
Measure whole-investigation time, tokens, spend and rework; retain missing values
as unknown. Do not let a summed score hide a lost critical mechanism.

`scripts/research_trials.py` summarizes externally judged paired records:

```json
[
  {"case":"case-a","strategy":"baseline","verified_contributions":["mechanism-a"],"seconds":60,"dollars":null,"tokens":800,"judgment_evidence":"private/review-a.md"},
  {"case":"case-a","strategy":"candidate-method","verified_contributions":["mechanism-a","mechanism-b"],"seconds":80,"dollars":null,"tokens":1000,"judgment_evidence":"private/review-a.md"}
]
```

Run `python scripts/research_trials.py PRIVATE_TRIALS.json --baseline baseline
--candidate candidate-method --output PRIVATE_REPORT.json`. It rejects unpaired
cases and preserves both additions and misses. It does not inspect judgment
files, estimate significance, weight contributions or select a winner.

## Optional Exa adapter

[Exa's current search contract](https://exa.ai/docs/reference/search) supports
search modes, domain filters, highlights and cost metadata. Its API requires a
key; an open SDK does not make the hosted search service open source.

With `EXA_API_KEY` supplied through the environment, run:
`python scripts/reference_provider.py exa-search "MECHANISM QUESTION" --domain
github.com --output PRIVATE_RESULT.json`. Domain filtering is optional: GitHub-only
search can miss important implementations elsewhere. Inspect returned primary
material; highlights are discovery aids. The helper saves a private response and
latency receipt, makes one request, refuses redirects and performs no retries.
No key is placed in output. Exact costs remain those returned by the service.
Live performance is unqualified until actual paired trials and implementation
probes support promotion. Preserve useful competing providers and conditional routes.

# Maintain the reusable process

Keep the full user outcome in view. Before committing to a consequential
approach, inspect existing solutions, underlying mechanisms, likely bottlenecks
and alternative routes that could remove unnecessary work. When results fail,
investigate causes and structurally similar solutions. Test promising adaptations
and reconsider the approach when repeated patches yield no new evidence.

Use the canonical skill at `skills/reference-driven-development/`. Change the
producing helper or handoff when a correction should affect execution. Prose,
packet validity and passing mechanics tests do not prove real-world effectiveness.

For UI changes, read `references/ui-continuity.md` within the skill. Preserve
actual image inputs, reference-led exploration, precise font and density anchors,
fresh-context critique and complete rendered journey checks.

# Keep this repository current

Commit and push reviewed coherent improvements during authorized work. Run checks
appropriate to the change, inspect the staged content and verify the remote
result. Do not leave a large verified implementation unpublished while reporting
only a documentation commit. Report remaining unverified work precisely.

Publish reusable mechanisms, authored fixtures and qualified tools. Exclude
private source archives, captures, credentials, research logs, user project names
and project-specific narratives. Retain their useful conditional lessons without
exporting their private evidence. Keep original records in the private workspace.
Preserve upstream licenses and attribution. Do not infer general performance
from a narrow fixture or describe a planned operation as executed.

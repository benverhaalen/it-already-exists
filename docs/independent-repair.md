# Preserve independent checks through implementation and repair

Use this route when independent reconstruction is the intended access policy.
For source-assisted work, retain independent behavioral checks without imposing
unneeded implementer isolation.

1. Observe the complete reference journey. Bind version, environment, inputs,
   state, fresh captures and installed artifact bytes.
2. Export a reviewed behavioral specification and permitted assets. Keep reference
   source, evaluator internals, raw restricted evidence and credentials outside
   the implementer's actual access boundary.
3. Build through a reviewed command catalog and qualified execution boundary.
   Keep inference access separate from generated-code execution.
4. Install the delivered bytes and independently compare state, trajectory,
   appearance and timing. Repeat the reference when necessary to distinguish
   environment noise from a real discrepancy.
5. Export reviewed counterexamples tied to the current source, candidate bytes
   and fixed comparison contract. Correct unsupported analyst assumptions rather
   than forcing them into the repair.
6. Continue the same implementation history and spent budgets through repair.
   Rebuild, reinstall and repeat the complete independent comparison.

Keep development signing identity stable when update behavior is a property.
Reinstalling after a signature mismatch changes state and is not proof of update
compatibility. Any permitted reset needs separate evidence and a new journey.

Matching settled content does not establish full-screen, intermediate animation,
latency, unobserved behavior or universal equivalence. Pin comparison regions and
tolerances to actual evidence; retain timing differences even when state passes.
Observer probes and captures are not necessarily atomic or device attestation.
